# Decisions

- Limited visible listing contract `priceComponents` to latest calculation components instead of full history to reduce query, serialization, and cache payload size.
- Wrapped default listing prepared-data cache writes in a short cache lock; if the lock is busy, render uncached to avoid request timeouts during cold-cache stampedes.
- Disabled prepared view-data caching for city SEO pages because long-tail city URLs plus local/regional sections create large DB-cache payloads; city pages still reuse shared contract metric caches.
- The August 20 incident was a shared MySQL communication stall, not a slow municipality or route-specific query. Production logged 196 PDO/MySQL timeouts across two periods, and MySQL logged `MY-013935` at the same time. CPU, memory, locks, connection capacity, and uptime did not show resource exhaustion.
- The database cache held about 408 MB: about 298 MB of contract-detail payloads, 77 MB of contract-list metrics, and 33 MB of SEO listing payloads. A metric cache row was about 1.43 MB, and transient `ContractListCacheService` resolutions could download it repeatedly in one request.
- `AppServiceProvider` now binds `ContractListCacheService` as request-scoped, so independently resolved consumers share its existing memoization. A container-resolution regression test guards the binding because the old memoization test manually reused one instance.
- Move the single-replica production application's default cache to the persistent file store as the immediate infrastructure mitigation. Keep queue persistence in the database. Remove old database-cache rows only after the file-store deployment is healthy.
- Focused memoization and scheduler tests pass, Pint passes, and the production asset build passes. The full suite has 21 unrelated existing failures in company-market comparison and home-trend tests. Replacing the new scoped binding temporarily with the old transient binding reproduced the same 17 failures in those isolated test files, so the release change does not cause them.
- Production deployment `a4cd66b5-50b2-425b-b9be-0656fc12ac54` released commit `84c033680ec24c345a733cdbdeb9713e5e4d7c27` successfully on 2026-08-21. The active default cache is `file`, verified cache files were written under persistent storage, and the four incident URLs rendered successfully before and after the obsolete database cache was truncated. The database cache has zero rows, MySQL disk use fell by about 0.44 GB, and no post-deploy maximum-execution-time error was found.
