# Decisions

- 2026-05-22: Started task to add daily EEX electricity futures EOD collection.
- 2026-05-22: Store EEX futures in a new `electricity_futures_eod_prices` table keyed by exchange/commodity/pricing/product/area/short_code/maturity/trade_date. EEX may revise recent settlement values, so imports use upsert rather than insert-ignore.
- 2026-05-22: Default collection targets EEX Nordic System Price plus Nordic zonal Base Year futures (DK1, DK2, FI, NO1-NO5, SE1-SE4), using verified short codes from the EEX product-code file/API. Baltic power futures are not configured because the current EEX product-code file does not expose Baltic power year future short codes for this endpoint.
- 2026-05-22: The command defaults to a 45-day rolling request window and caps older requested start dates because the public EEX chart API does not return older history.
- 2026-05-22: Scheduled `futures:fetch-eex` daily at 20:30 Europe/Helsinki after the EEX settlement window. Validation passed with targeted feature tests, PHP syntax checks, and live dry-runs against FI/DK1/NO1/SE3 requests.
- 2026-05-22: Extended the configured EEX instruments from year-only to month, quarter, and year tenors for every configured Nordic area. EEX maturity strings are `YYYYMM`: months use the delivery month, quarters use the quarter start month, and years use January (`YYYY01`). Verified all configured area/tenor/short-code combinations with a live dry-run using one month, quarter, and year maturity per area.
- 2026-05-22: Aligned default maturity generation with EEX delivery dropdown examples. For a May 2026 run, monthly defaults now include April-November 2026 (`months_back=1`, `months_ahead=7`) and yearly defaults include Cal-27 through Cal-32 (`years_ahead=6`). The command still lets operators pass explicit `--maturity` values or limit by `--tenor`.
- 2026-05-22: Tested out-of-bounds maturity values. EEX returns HTTP 200 with empty data (`price-ticker.data = []`, chart series empty) rather than an error. The command now dynamically probes `price-ticker` for each instrument/tenor and fetches EOD data only for the contiguous valid maturity range; scan ceilings are safety limits, not assumed max maturities.
- 2026-05-22: Added `futures:backfill-eex` as an explicit "all available public history" command. Because the EEX public chart endpoint only returns about 45 days, this command delegates to the normal fetch path without a custom start date and cannot recover older history.
- 2026-05-22: Added polite EEX request throttling in `EexFuturesService`: first request is immediate, subsequent public API calls wait a random delay around 15 seconds by default (`request_delay_seconds` +/- `request_delay_jitter_seconds`). Unit tests skip the sleep.
