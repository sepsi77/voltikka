## Source-fact stage constraints

- V5 requires per-component energy_rule. Monetary General/Time/Season components use an object;
  all other component families use null. Unknown objects assert no new facts.
- Known rules are FixedPrice, AdjustableTariff, AbsoluteDiscount or PercentageDiscount. Actual and
  normal prices stay in existing amount/normal_amount fields. Own rule bounds, source operand and
  source floor remain separate. A normal basis has its own evidence and cannot inherit an actual lock.
- Structured nonpercentage discount_value is a reduction in all profiles: normal 9 minus reduction 5
  bills 4. The manager retracted the contrary premise; this is not an upstream API semantic change.
  API clipping at zero does not prove a continuing seller floor.
- Only complete supported Finnish/English source clauses establish known facts. Recognized harmless
  marketing/contact text can coexist with pricing. Natural General forms require proven source scope;
  Time/Season remain named. Compatible/disjoint dated periods can match independently; conflicting
  overlaps fail. A current normal adjustable rate can support the exact source-bound typed Normal
  continuation, never a future price guarantee. Unsupported/ambiguous pricing remains Unknown.
  The bounded forms, practical examples and remaining limits are in decisions.md.
- Real V5 publication requires full validation against the exact locked source observation/snapshot.
  A default V4 dispatcher must retain a valid V5 publication for the unchanged source instead of
  erasing its facts. Changed sources/new IDs do not gain automatic V5 selection.
- Parser opt-in is explicit (`withEnergyRules: true`); defaults and Historical remain false. All four
  current financial service paths require exact batched `energy_rules_valid` proof before opt-in.
  Failed required proof excludes rather than falling back. VAT copies preserve typed rules and
  scale only monetary operands/floors.
- Calculated-cost schema 19 is the local cache release boundary, not producer activation or a history rewrite.
- Activation requires a separately approved coordinated switch of all five current profile keys
  (three versions and two asset paths), fresh tests and production-data impact/performance review,
  plus separately approved reinterpretation. See `release-plan.md`; no ad hoc V5 production is approved.
