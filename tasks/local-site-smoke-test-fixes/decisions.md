# Decisions

- Company-page HTTP 500 errors and stale Spot data were resolved by the development production-data sync. They are not part of this task.
- Local URL/storage setup, asset preloads, bill validation, solar copy, and broken external-logo handling remain.
- Parallel executor agents own independent code areas. The manager reviews and integrates their changes, then runs combined regression and browser checks.
- Local setup now uses `APP_URL=http://127.0.0.1:8000`, the standard `public/storage` link, cleared local caches, and a regenerated ignored sitemap. `.env.example` carries that default and the root setup command documents `php artisan storage:link`, so a new checkout does not recreate the wrong-origin or missing-logo problem. Representative logos, canonical URLs, and sitemap URLs now use the active local origin.
- Standalone bill comparison treats a numeric value below 1 kWh as a Livewire validation error, clears it after a valid value, and exposes the message through `role=alert`, `aria-invalid`, and `aria-describedby`.
- The solar result partial receives the normalized 0.5–20 kWp effective size for both the live and Helsinki example paths. Thus the example label and the calculation cannot disagree after a changed or clamped input.
- The layout relies on Laravel Vite's generated CSS preload/modulepreload tags and Livewire's own versioned script tag. The duplicate manual Vite preload block and stale unversioned Livewire preload were removed.
- Visible public logo tiles and Product, ItemList, and Organization JSON-LD use only `Company::getLocalLogoUrl()`. External-only companies stay on initials, so dead seller URLs trigger no browser request and never enter structured data. Non-browser API/video consumers can still use `getLogoUrl()` as an external fallback. Local URL resolution checks that the recorded file exists and prefers an existing optimized WebP path.
- Final browser verification passed all five fixes: correct local canonical/logo origin, one standards-correct Vite module request with no stale Livewire preload, accessible zero-kWh feedback and recovery, the 8,0 kWp solar heading, and external-logo initials with no JSON-LD logo. It initially still observed external logo request failures, so public logo tiles were tightened to local-only before final completion. Company and Spot pages stayed HTTP 200.
- That browser run found one separate malformed company-page SVG `viewBox="0 0 24"`. It was corrected to `0 0 24 24`, regression-tested, and verified in rendered HTML.
- Combined manager verification passed 29 bill/solar tests with 101 assertions, 168 preload/logo tests with 517 assertions, focused contract-detail/schema checks, 55 all-repository logo tests with 127 assertions, and the company SVG regression. The full Laravel suite passed 1,711 tests with 6,106 assertions and retained only the two unrelated known failures: the duplicate monthly Spot-average fixture and strict floating-point identity assertion. Pint, task JSON validation, and `git diff --check` passed.
- Zero is invalid for both required bill numbers. Consumption uses HTML `min=1`; price uses `min=0.01`. Locked component properties retain each last-accepted value. If a visitor enters consumption below 1 kWh or a price at or below 0 €, the update restores that prior value before recalculation and shows an accessible error. Thus an invalid zero never reaches `BillComparisonService`, and displayed results remain consistent with the restored inputs instead of appearing to process zero. Browser verification confirmed 0 restored 400 kWh and 35 €, results retained those valid values, and later valid entries cleared the errors.
