# Offline lagged futures level experiment

Scope: this folder only. Do not change application/configuration, the database, production, dependencies, or prior research. `spec.md` is the frozen protocol. `CLAUDE.md` links to this file.

- `analyze.py` imports the prior verified export/ownership and calendar helpers read-only. `Evidence.laghedge()` changes the trade cutoff, not the delivery basket. Each historical retail date selects its own next-full-month basket and lagged vintage. A missing selected vintage slot blocks the full strip.
- Native histories retain corrected v3 observed-prefix/canonical-continuation chronology. Common histories use the exact intersection of usable historical dates across all five lags. Both require 10 prior observations. This separation prevents a training-date change from being mistaken for a lag effect.
- Only 30-day median forecasts are tested. The optional 14-day horizon is omitted. No lag, lambda, threshold, or other parameter is selected from results.
- New direction uses unrounded expected change; four-decimal expected change is a separate precision audit. Actual class uses the rounded same-basis actual-minus-current difference. Original v2 uses its saved price and direction only as a separate reference. Originals are never rewritten.
- `forecasts.*` retains every candidate, exclusion, source ID, method, basis, history date list, history counts/bounds, and H/N/R. `hedges.*` retains every fixed delivery month, fallback slot, and strict trade vintage. `cohorts.*`, `coverage.*`, `metrics.*`, `diagnostics.*`, and `history-sensitivity.*` separate native eligibility, primary intersection, matched-v2 reference, and common-history sensitivity.
- `verify.py` independently rebuilds raw unit ownership, expands raw futures to delivery days with Decimal, and checks closed-form EWMA weights. It verifies all dates/cohorts/errors/classes and 15 synthetic cases. Native L0 matches 147 actual-PHP v3 generated medians plus 297 retained PHP-verified 30-day exact pairs across both bases. No PHP or DB rerun is needed: retained actual-service evidence and its hash chain are checked before and after.
- `reproduce.py` runs only this folder's analysis, verifier and renderer twice. It requires byte-identical outputs and unchanged pinned inputs. `inputs.json` pins raw export, prior evidence, current forecasting source, and the frozen spec; prior direction-sensitivity pins and horizon reproducibility hashes are also checked.
- Run from root: `python3 tasks/forecast-lagged-levels/reproduce.py`. The report is under 600 words. Full term metrics are in CSV/JSON, not omitted from the analysis.

Result: lagged levels reduce canonical numerical errors but have little directional benefit. Common-history support does not change the canonical four-decimal forecasts. Earlier observed results show no consistent directional improvement. These are overlapping, already inspected, export-time cohorts. Continuity across the basis boundary is an assumption. Do not select a lag or release a model from this evidence.
