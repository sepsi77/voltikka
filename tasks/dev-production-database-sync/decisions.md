# Decisions

- The public entry point is `scripts/sync-production-database.sh`.
- Railway production MySQL is read through `railway run` with the explicit production project, environment, and MySQL service IDs from root `AGENTS.md`. Each Railway call has `RAILWAY_CALLER=skill:use-railway@1.2.2` and one stable `RAILWAY_AGENT_SESSION`.
- Credentials stay in injected environment variables and are never printed. `MYSQL_PUBLIC_URL` is preferred. A paired Railway TCP proxy domain and port can supply the public endpoint with injected `MYSQL*` credentials as fallback.
- The Laravel command writes only to an explicit `.production-sync-*` temporary file in `laravel/database`. It needs `VOLTIKKA_LOCAL_DATABASE_SYNC=1` and rejects any target with the same device and inode as the active `database/database.sqlite` file.
- Every Artisan child has a unique nonexistent `APP_CONFIG_CACHE`, `APP_ENV=local`, an empty `DB_URL`, and the explicit SQLite connection and temporary path. The Railway-target variables are set by its child `env` after Railway injection, so source `MYSQL_PUBLIC_URL` and `MYSQL*` credentials remain available.
- Before migration, the command's verification-only mode boots Laravel and proves that the effective default connection is SQLite and its effective main database path is the exact temporary target.
- The shell wrapper migrates the temporary target and swaps it into place only after all copy and validation work passes.
- Source reads use one `REPEATABLE READ`, read-only, consistent MySQL transaction. MySQL PDO uses unbuffered queries, and the copy engine moves one row at a time.
- The migrated target and production table lists are compared in both directions after exclusions. A non-excluded application table absent on either side fails closed, except for the one explicit local-derived `contract_source_observations` table while production schema lags. A target primary key or required no-default column absent from production also fails closed. Optional target columns can use their SQLite defaults.
- When production lacks `contract_source_observations`, the synchronizer first copies contracts and snapshots. A focused `ContractSourceObservationRebuilder` then loads and runs the existing `2026_07_30_000002_backfill_contract_source_observations.php` migration against the fresh target. This reuses the exact chronology algorithm instead of duplicating it, and final row-count, foreign-key, and SQLite integrity validation runs after reconstruction. When production later has the table, it is copied normally and the rebuilder does not run.
- The fresh target `migrations` table is preserved. Production-only application tables fail instead of being silently omitted.
- Local authentication, cache, queue, session, social-publication, and freshness-ledger tables are excluded because they are not public-site content and can cause unsafe local side effects.
- Foreign keys are disabled only while the fresh temporary SQLite file is filled. Source and target row counts for each copied table, `PRAGMA foreign_key_check`, and `PRAGMA integrity_check` must pass before replacement.
- The wrapper checks the local PHP PDO drivers, Railway CLI, `sqlite3`, and `lsof`. Its use checks cover the main database and existing `-wal`, `-shm`, and `-journal` sidecars.
- The active database is not opened or changed until the fresh target passes the command's row-count, foreign-key, and integrity validation. The wrapper then checkpoints and validates the fresh file before replacement.
- A plain copy of the main SQLite file is not a valid backup because a closed database can still have committed WAL state. The wrapper uses the `sqlite3` backup mechanism and integrity-checks the resulting timestamped `/tmp` backup.
- After the second use check, the wrapper checkpoints the active database, checks use once more, removes every old WAL/shared-memory/journal sidecar, makes the final possible `lsof` check immediately before rename, and atomically replaces the main file on the same filesystem. This prevents an old sidecar from being applied to the new database. `lsof` remains advisory, so the operator must stop local processes for the complete workflow.
- The first real sync stopped safely before production access because the shell tried to reassign its read-only `RAILWAY_AGENT_SESSION`; the internal value now uses `SYNC_RAILWAY_AGENT_SESSION`. The second reached production read-only and stopped safely before local replacement because production did not yet have `contract_source_observations`. Both failures removed their temporary targets and kept the active local database unchanged.
- The final real sync completed through the read-only Railway MySQL connection. It copied 24 content tables, reconstructed 772 source-observation episodes from 772 immutable snapshots, passed row-count, foreign-key, and integrity checks, backed up the old local database to `/tmp/voltikka-database-20260731-140521-48994.sqlite`, and atomically replaced `laravel/database/database.sqlite`.
- Post-sync checks found 423 active contracts, no active contract without a current source-observation pointer, current Spot rows through 2026-07-31 21:45 UTC, and empty excluded users, jobs, social-publication, and freshness-ledger tables. Production was read only and no production service or data was changed.
- The final focused suite passed 25 tests with 99 assertions. Pint passed for all 9 changed PHP files. Shell syntax, task JSON, `git diff --check`, the synced SQLite integrity check, and representative listing, statistics, Spot, and company-page HTTP smoke tests passed. A final independent safety review found no blocking issue.
