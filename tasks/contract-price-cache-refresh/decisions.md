- Keep this first change inside ContractDetail. Non-selected consumption uses the existing single-contract evaluation, not the whole-market read-through cache.

- Cache retention, keys, refresh lifecycle, and service changes wait for the separate lifecycle investigation.

## Approved generation implementation

- Added one atomic shared active descriptor with public version, private UUID, and creation time. Candidate builds write all eight preset payloads and company/5,000 privately. Company receives the exact candidate metrics. Each write must succeed, every required payload must pass readback, and promotion compares the starting descriptor under the shared transition lock. Builders release each hydrated preset.
- Complete imports stage replacement only after successful required statistics. `price_cache_refresh` is a required safe aggregate stage. Partial imports and statistics failures retain the prior generation. Statistics timing and queue scheduling are unchanged. The coordinator forgets only the owned sitemap key; no store flush or table truncate remains.
- Active list/company prices persist across midnight and beyond 48 hours. Rankings reuse retained metrics. Immediate interpretation/EEX/manual version invalidations remain immediate and reject concurrent candidates. Prior tracked payloads have one hour of reader grace after switching, followed by bounded explicit physical cleanup; retirement failure never undoes activation. The initial TTL-only cleanup was corrected during review.
- Current active pointed/published source identities, ownership, and publication state guard cached canonical facts. The initial relational-publication gate was removed during review: it must never gate canonical listability. Changed or mismatched old identities become typed exclusions; current company/ranking/prepared-page fingerprints cannot bypass that guard. This does not change canonical calculator semantics or freeze the database. Pointer-free fixtures keep cold behavior. Direct custom calculations and non-selected detail tiers remain current calculations.
- `ContractListCacheService::calculatedAt($consumption)` exposes the actual stored calculation timestamp. Ranking wrapper v3 retains it. The subsequent detail unit changed `heroVerdictNote()` from `now()` to retained evidence (see below). The generation executor did not edit ContractDetail, its presenter tests, or Livewire context.

## Review corrections and final verification

- Removed `relational_pricing_published` from cache evidence and eligibility. Current pointed/published identity, snapshot ownership, and publication status remain required. The typed canonical outcome decides listability. Regression coverage now keeps a corrected, detected hidden-price increase listed despite blocked relational publication, preserves the corrected canonical total, rejects changed source identity, and still excludes a genuinely incomplete current canonical result.
- Replaced TTL-only retirement with a durable retirement index and non-expiring manifests. A transition records cleanup ownership before switching the pointer. If that state write fails, activation does not start. Retired payloads remain throughout one hour of reader grace. Cleanup failures cannot undo an activation.
- Added `contracts:cleanup-price-cache` every five minutes, with one-server and overlap protection. Each invocation examines at most 20 tracked generations and attempts at most 100 payload deletions. It physically deletes exact owned keys and retains partial manifests/index state until deletion succeeds. It rechecks and skips the active generation under the shared transition lock. Cold writes use the same lock and extend retired-generation grace, so cleanup cannot race a late write. No cache-table scan, unrelated-key deletion, store flush, or truncate is used.
- Database tests inspect physical rows directly without first reading retired payload keys. They verify grace, actual row removal, failure retry state, active/unrelated payload retention, bounded batches, late writes, and cleanup-state write failure before activation. The command reports a non-zero exit on failure for central scheduler logging.
- Accepted limitation: cached phase rates, annual totals, and offer facts can remain from yesterday until explicit refresh. The cleanup schedule does not rebuild market prices or advance dated phases. Direct calculations remain outside this retention policy. The separate detail owner's stored-date fix is preserved.
