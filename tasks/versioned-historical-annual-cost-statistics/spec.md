# Versioned historical annual-cost statistics

## Goal

Rebuild historical annual-cost statistics with the current annual-pricing algorithm while preserving the evidence that was available on each statistics date. The public statistics page must never connect or compare annual-cost points that use incompatible calculation methods.

## Requirements

- Version derived annual-cost snapshot and aggregate rows independently from observed unit-price facts.
- Preserve historical `energy_price`, `spot_margin`, `spot_total_energy_price`, and `monthly_fee` evidence.
- Recalculate historical annual costs from the contract universe and prices observed on each date, not today's active-contract set.
- Use only date-bounded structured prices, Spot history, and futures evidence from the target date or earlier. A dedicated retrospective interpretation may complete later and may use explicitly graded first-immutable or last-observed text as a continuity backcast, but deterministic historical validation must prevent that text from introducing unsupported billed amounts, promotion timing, continuations, or deceptive-price claims.
- Never apply today's current canonical pricing JSON to an old date.
- Spot annual costs must use the current forward estimator when the required as-of curve exists and its typed rolling-365 fallback otherwise.
- Supplier-adjusted open-ended annual costs must use an as-of price episode and as-of market evidence. Unsupported historical reconstruction must fail closed or use the estimator's explicit typed fallback.
- Store enough method and estimate-basis provenance to prevent mixed-method 30-day changes, since-start changes, weekly/monthly averages, and sparklines.
- Current daily collection and historical rebuilding must produce the same method-version contract for the same date and evidence.
- Do not rewrite immutable source evidence. Derived statistics can be replaced only after the new version passes validation.
- Keep historical rows from the previous method available for audit unless a documented migration safely replaces only derived data.
- The public page and CSV must explain and expose the active annual-cost method version and fallback basis.
- Add regression tests for look-ahead bias, survivor bias, missing old curve vintages, method cutovers, cache invalidation, and current-page values.

## Current implementation boundary

The typed exact-date evidence resolver, calculator, annual-only writer, and dry-run-by-default historical rebuild command are implemented for shadow `annual_cost_as_of_v1` data. Historical dates and contracts use the union of exact-date snapshots and components; component-only identities become typed exclusions, while snapshot-only canonical evidence remains eligible. Apply requires one complete three-consumption result set and exact-target Spot evidence. Canonical current daily calculation writes the same AsOf method inside its required date transaction, but it adapts the exact canonical outcomes already calculated for the public ranking instead of invoking the strict historical calculator. Current provenance uses batched current pointers and does not query `price_components`. Feature-off and observed historical runs remain legacy-only. Public readers and caches are method-isolated and the CSV exports every method for audit. Company comparison now supports either active annual method and reads AsOf seller totals only from the versioned annual table. Every public annual trend uses one shared compatibility guard. Stored compatibility remains strict for audit, while aggregate median presentation derives its AsOf regime from the dominant estimate method in valid basis counts. Minority estimator changes do not split a median line; dominant changes still create gaps. Weekly/monthly statistics views append the latest daily median at its exact date and show restrained point markers. Daily views mark only each series' latest non-null point, so a current value immediately after a method gap stays visible without adding markers to every historical day. Spot win rates use only each segment's newest regime. The main endpoint rejects a stale canonical AsOf row after a feature-off recalculation. Aggregate market insights compare a deterministic same-key segment intersection rather than requiring one global key. `annual_cost_as_of_v1` has been active in production since 2026-08-09. Legacy rows remain unchanged for rollback.

## Historical LLM evidence integration

The isolated LLM backfill discovers pre-2026-07-23 exact snapshot+component episodes in deterministic, memory-bounded 25-contract chunks, persists them in dedicated audit tables, and can run non-publishing strict-schema analyses. Builder v4 stores one per-day record with exact snapshot/component identities and a normalized economic digest. A semantic fingerprint permits analysis reuse; a separate exact manifest fingerprint binds the reviewed plan, apply pass, stored episode, queued job, and later resolver read to the same row identities and values. Command planning streams chunks and retains only compact fingerprints/actions, counts, and selected dispatch identities. Dry run stops after this pass. Apply verifies the exact plan hash with zero writes, then repeats deterministic discovery inside one transaction to persist full inputs and manifests. The command accepts only exact valid ISO dates. Populated audit tables refuse migration rollback, while empty partial MySQL DDL state is retry-safe. Historical input uses the normal flat key set plus explicit control-only provenance.

Backcast text can recover stable pricing-model and adjustment-mechanism facts. Historical addendum v3 and backcast validator v2 bind every numeric billed/package fact one-to-one to a cited structured component by the normal validator's shared canonical type mapping, exact source payment unit, amount role, and component-scoped discount timing. They reject duplicate billed rows, wrong-scope package allowances, recurring-period dates, numeric consumption effects, and every `detected` backcast deception claim before parser acceptance. Historical requests use one 100-second HTTP attempt per model call so an initial call plus two repairs fit the queue envelope. All current and historical queue retries retain complete attempt/cost history.

The versioned AsOf resolver consumes exactly one validated current-fingerprint historical analysis only when the immutable source path returns no covering source observation. Exact manifest identity and economic-value matching, recomputed semantic/manifest/analysis fingerprints, empty validation errors, and a fresh canonical parser pass are mandatory. Ambiguous or invalid source chronology never falls back. The later retrospective completion timestamp, evidence grade, and dedicated episode/interpretation IDs are explicit in stored provenance. Old analysis versions can coexist and are ignored rather than making the current fingerprint ambiguous. Annual arithmetic remains deterministic. Eligible episodes can align method semantics across the July rollout, but component-only days and genuine method transitions remain unavailable or visible as chart gaps. The integration does not activate `annual_cost_as_of_v1`; the public method stays `annual_cost_legacy_v1`.
