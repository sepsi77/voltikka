# Decisions

- Historical recalculation means an as-of backtest. It must not use current active contracts, current source pointers, today's canonical interpretation, or a future curve vintage.
- Observed unit-price facts and derived annual costs have different provenance. The task versions annual costs without rewriting observed unit-price history.
- The existing `contracts:calculate-price-statistics --date=...` command is not a historical reprocessor because it selects today's `active_contracts` and current canonical JSON.
- The existing relational backfill is evidence-safe but does not run the new forward annualisation models.
- FI futures vintages before 2026-04-08 are unavailable. Historical Spot dates without complete as-of curve evidence must use the typed rolling-365 fallback or remain unavailable; they must not read a later curve.
- Exact-date relational components are the historical contract-universe authority from 2026-01-21. Current `active_contracts`, current source pointers, and current canonical JSON are forbidden in the rebuild.
- Complete immutable payload chronology is only generally available from about 2026-07-23, and exact historical publication state cannot be reconstructed. The first method version therefore uses exact-date relational pricing and fails closed or holds flat when a reset mechanism or supplier episode is not proven.
- Historical Spot forward pricing is likely possible from 2026-05-01. Earlier dates use the strict rolling-365 fallback. No same-day or later EEX trade date can enter a target date.
- Preserve existing snapshot rows as observed/legacy compatibility data. Store new versioned annual costs in a separate annual-only table so old and new methods can coexist without duplicating or rewriting unit-price facts.
- Keep `pricing_basis` for source provenance. Add a separate annual method version, calculation basis, estimate method, compatibility key, and typed provenance.
- The first release builds the new method as shadow data. Public readers stay on the legacy method until the full local and production dry runs pass.
- Persistence foundation: `contract_price_annual_costs` owns per-contract annual outputs with date + contract + consumption + method identity. Daily aggregates include method in their identity. Existing annual aggregates are `annual_cost_legacy_v1`; existing unit aggregates are `unit_statistics_v1`.
- Superseded: the first persistence draft made `contract_price_daily_statistics.method_version` non-null. It now stays nullable in storage for application rollback compatibility; the model and every new writer still assign it explicitly.
- Rollback refuses to remove method versioning if multiple rows conflict under the old aggregate identity. It does not select or delete a method implicitly.
- `CONTRACT_STATISTICS_ANNUAL_METHOD_VERSION` defaults to `annual_cost_legacy_v1`. No current reader or producer was activated for `annual_cost_as_of_v1` in this unit.
- Superseded: the first draft required a perfect stored hourly count. Stored rolling Spot evidence now uses the documented 98% threshold below; exact raw reconstruction remains strict.
- Historical supplier-price episodes use only `contract_price_snapshots` through the target date. Observed target evidence wins. Canonical or another supported snapshot basis is considered only through an explicit basis argument. A matching run is left-censored unless an immediately preceding same-basis calendar-date row proves a rate or fee change.
- The earlier evidence-foundation unit did not implement or activate the historical annual calculator, annual writer, rebuild command, current producer integration, or public readers.
- `AsOfAnnualCostEvidenceResolver` owns the batched exact-date evidence boundary. The universe is the union of exact-date snapshots and components. A snapshot supplies safe historical classifications and masks; a component-only identity becomes a typed unavailable exclusion. Optional canonical input requires exactly one covering source snapshot and one uniquely latest parser-valid interpretation completed by the target day. It does not read active membership, current canonical materializations, or current pointers.
- `AsOfAnnualCostCalculator` implements the typed shadow calculation core for 2,000/5,000/18,000 kWh. It resolves as-of Spot once and historical supplier candidates/anchors once. Canonical Spot uses the typed forward/fallback estimate. Relational Spot receives annual day/night equivalents. Missing Spot is unavailable. Strict recurring-reset canonical evidence uses an explicit exact-date relational hold-flat path in v1, not the canonical reset estimator, because that estimator can use a realized seasonal fallback unavailable on the historical date.
- Relational open-ended fixed prices stay flat unless strict dated canonical output proves the narrow supplier-adjusted candidate. Existing snapshot annual values are null/non-null eligibility masks only. Every available total is finite, non-negative, and no more than 50,000 euros. Compatibility identity includes the annual method, calculation basis, estimate method, and estimate basis.
- This unit still does not add an annual persistence writer, rebuild command, current producer integration, or public reader activation. The configured/public method remains `annual_cost_legacy_v1`.

Its aggregate percentiles use the existing linear interpolation. Mixed pricing evidence is `mixed_evidence`; mixed calculation or estimate evidence is `mixed`. Aggregate compatibility is a SHA-256 hash of the sorted unique member compatibility keys.
