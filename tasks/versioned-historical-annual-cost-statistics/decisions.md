# Decisions

- Historical recalculation means an as-of backtest. It must not use current active contracts, current source pointers, today's canonical interpretation, or a future curve vintage.
- Observed unit-price facts and derived annual costs have different provenance. The task versions annual costs without rewriting observed unit-price history.
- The existing `contracts:calculate-price-statistics --date=...` command is not a historical reprocessor because it selects today's `active_contracts` and current canonical JSON.
- The existing relational backfill is evidence-safe but does not run the new forward annualisation models.
- FI futures vintages before 2026-04-08 are unavailable. Historical Spot dates without complete as-of curve evidence must use the typed rolling-365 fallback or remain unavailable; they must not read a later curve.
- Exact-date relational components are the historical contract-universe authority from 2026-01-21. Current `active_contracts`, current source pointers, and current canonical JSON are forbidden in the rebuild.
- Complete immutable payload chronology is only generally available from about 2026-07-23, and exact historical publication state cannot be reconstructed. The first method version therefore uses exact-date relational pricing and fails closed or holds flat when a reset mechanism or supplier episode is not proven.
- Historical Spot forward pricing is likely possible from 2026-05-01. Earlier dates use the strict rolling-365 fallback. No same-day or later EEX trade date can enter a target date.
- Preserve existing snapshot rows as observed/legacy compatibility data. Store new versioned annual costs in a separate annual-only table so old and new methods can coexist without duplicating or rewriting unit-price facts.
- Keep `pricing_basis` for source provenance. Add a separate annual method version, calculation basis, estimate method, compatibility key, and typed provenance.
- The first release builds the new method as shadow data. Public readers stay on the legacy method until the full local and production dry runs pass.
- Persistence foundation: `contract_price_annual_costs` owns per-contract annual outputs with date + contract + consumption + method identity. Daily aggregates include method in their identity. Existing annual aggregates are `annual_cost_legacy_v1`; existing unit aggregates are `unit_statistics_v1`.
- Superseded: the first persistence draft made `contract_price_daily_statistics.method_version` non-null. It now stays nullable in storage for application rollback compatibility; the model and every new writer still assign it explicitly.
- Rollback refuses to remove method versioning if multiple rows conflict under the old aggregate identity. It does not select or delete a method implicitly.
- `CONTRACT_STATISTICS_ANNUAL_METHOD_VERSION` defaults to `annual_cost_legacy_v1`. No current reader or producer was activated for `annual_cost_as_of_v1` in this unit.
- Superseded: the first draft required a perfect stored hourly count. Stored rolling Spot evidence now uses the documented 98% threshold below; exact raw reconstruction remains strict.
- Historical supplier-price episodes use only `contract_price_snapshots` through the target date. Observed target evidence wins. Canonical or another supported snapshot basis is considered only through an explicit basis argument. A matching run is left-censored unless an immediately preceding same-basis calendar-date row proves a rate or fee change.
- The earlier evidence-foundation unit did not implement or activate the historical annual calculator, annual writer, rebuild command, current producer integration, or public readers.
- `AsOfAnnualCostEvidenceResolver` owns the batched exact-date evidence boundary. The universe is the union of exact-date snapshots and components. A snapshot supplies safe historical classifications and masks; a component-only identity becomes a typed unavailable exclusion. Optional canonical input requires exactly one covering source snapshot and one uniquely latest parser-valid interpretation completed by the target day. It does not read active membership, current canonical materializations, or current pointers.
- `AsOfAnnualCostCalculator` implements the typed shadow calculation core for 2,000/5,000/18,000 kWh. It resolves as-of Spot once and historical supplier candidates/anchors once. Canonical Spot uses the typed forward/fallback estimate. Relational Spot receives annual day/night equivalents. Missing Spot is unavailable. Strict recurring-reset canonical evidence uses an explicit exact-date relational hold-flat path in v1, not the canonical reset estimator, because that estimator can use a realized seasonal fallback unavailable on the historical date.
- Relational open-ended fixed prices stay flat unless strict dated canonical output proves the narrow supplier-adjusted candidate. Existing snapshot annual values are null/non-null eligibility masks only. Every available total is finite, non-negative, and no more than 50,000 euros. Compatibility identity includes the annual method, calculation basis, estimate method, and estimate basis.
- This unit still does not add an annual persistence writer, rebuild command, current producer integration, or public reader activation. The configured/public method remains `annual_cost_legacy_v1`.
- `AnnualCostStatisticsWriter` validates one complete date before a transaction, persists only available AsOf rows, replaces only that date and method in the annual-only and annual aggregate tables, and does not warm caches. Its aggregate percentiles use the existing linear interpolation. Mixed pricing evidence is `mixed_evidence`; mixed calculation or estimate evidence is `mixed`. Aggregate compatibility is a SHA-256 hash of the sorted unique member compatibility keys.
- Date summaries count all typed results and unavailable reasons. Aggregate `basis_counts` include pricing basis, calculation basis, estimate method, and estimate basis from available contributors only; unavailable reasons stay in their separate map. Unavailable results never become annual-only rows.
- `contracts:rebuild-annual-cost-statistics` selects the union of snapshot and component dates, defaults through yesterday, and is dry-run unless `--apply` is present. Contract filtering and `--limit` are dry-run diagnostics only. A date exception fails the command and does not write that date. The command has no schedule and no cache warming.
- Current and historical legacy statistics cleanup is method-scoped. It can replace only `unit_statistics_v1` and `annual_cost_legacy_v1`; it preserves AsOf daily aggregates and the annual-only table. The current-state calculation command rejects explicit past dates with rebuild guidance.
- The shared supplier seasonal index is not date-bounded. If a canonical historical supplier outcome selects it, AsOf v1 discards that total and recalculates exact-date relational pricing held flat with `hold_current_supplier_price` and explicit provenance. Broad calculator exception conversion was removed so programming errors fail the complete date safely.
- The writer/rebuild unit is complete. Current producer integration and production activation remain pending. The configured/public method remains `annual_cost_legacy_v1`.
- Public method isolation is explicit, not global: unit queries use `unit_statistics_v1`, annual queries use the configured active method, and mixed page queries use the model's OR scope. All production annual-cost readers were migrated, and energy-price forecast/history queries were not changed.
- The main statistics endpoint date remains owned by current unit rows at the expected pricing basis. Active annual rows can join that date with `pricing_basis=mixed_evidence`. Historical annual rows stay method-filtered. Weekly/monthly annual periods with more than one non-null compatibility key are null, and annual 30-day/since-start deltas require equal keys.
- Prepared statistics cache schema is v13 and includes the active annual method in both key and active-row fingerprint. CSV is an audit export of all versions and marks only the configured active annual rows.
- Company annual snapshot columns are still legacy-only. `CompanyMarketComparisonService` explicitly fails closed when the active method is not legacy. A later production activation requires versioned company annual storage or a versioned join; it must not compare AsOf market rows with legacy seller rows.
- Superseded: the first current-date integration invoked the strict historical calculator. Current daily collection now adapts the exact canonical outcomes as described below.
- Historical rebuilds use the date-bounded resolver. Current daily collection does not parse current materialized JSON again; it reuses the exact typed canonical outcomes already calculated for current snapshots and ranking.
- The rebuild command rejects `--apply` with `--contract` or `--limit` before it checks whether the selected range contains snapshots. An empty range therefore cannot bypass the no-partial-apply rule. Today remains invalid for rebuild, and the current calculate command accepts only today, not future dates.
- Superseded: current parity coverage originally used the strict historical calculator and recurring-reset v1 hold-flat behavior. That current-date integration was wrong because strict historical episode rules can differ from the safe current source pointers already used by public canonical ranking.
- Current daily AsOf rows now adapt the exact `CanonicalPricingOutcome` slots retained for every processed current contract, including contracts excluded before numeric snapshot persistence. `CurrentCanonicalAnnualCostResultFactory` does no pricing calculation. It batch-loads current contract identity, optional new snapshot IDs, current observation, source snapshot, and published interpretation pointers; `price_component_ids` is empty and current canonical collection issues zero `price_components` queries. Each contract yields three typed results, so an all-excluded but non-empty full run can remove stale AsOf rows without violating the empty-apply guard.
- The current adapter preserves each outcome total and estimate method, derives a namespaced estimate basis from typed Spot, supplier-adjusted, or reset evidence (or the disclosed canonical timeline), carries assumptions and nested flags, and uses the outcome's supplier episode start. Missing, excluded, and out-of-range results are unavailable, so date-wide writer replacement removes stale rows.
- Strict historical reconstruction remains in `AsOfAnnualCostCalculator` and the rebuild command. It still forbids current pointers and keeps its conservative hold rules. Feature-off remains legacy-only. The configured/public method remains `annual_cost_legacy_v1`.
- Current parity coverage now includes fixed, short-term annualized, Spot, forward-shift reset, supplier-adjusted current-source-anchor, package, and Hybrid outcomes at all three consumptions. The supplier case has no resolving historical snapshot run and proves the stored current row remains the canonical forward estimate instead of becoming the historical hold-flat fallback.
- Stored AsOf `rolling_365d` rows now use a typed 98% evidence threshold instead of requiring perfect hourly completeness. The production snapshot has exact period-end identities and finite values but typically 8,702–8,704 of about 8,760 hours (about 99.3%); rejecting those rows made every historical Spot result unavailable even though the public estimator accepts the 365-date window. The 98% floor permits small source gaps while rejecting materially incomplete windows. Stored hours must remain positive and no greater than the DST-aware expected count. Exact raw reconstruction remains one unique row per expected UTC hour. Coverage does not repair a gap with later evidence: future stored and hourly rows remain outside the as-of boundary. AsOf results carry complete/partial status, coverage ratio, expected hours, and actual hours; annual results copy these facts into provenance. Forward Spot can use an accepted partial shape only as the historical day/night offset, while its future level and typed estimate/fallback basis remain unchanged.
- Superseded: company comparison no longer fails closed merely because AsOf is active. It branches by the configured annual method. Legacy still reads snapshot annual columns. AsOf seller rows come only from `contract_price_annual_costs` and join exact-date snapshots only for company identity and the observed unit-rate guard. Latest-date selection requires an active-method market aggregate and a matching versioned seller row for the same date, segment, basis, and consumption. Canonical current and explicitly historical observed fallback payloads both work when their matching AsOf rows exist.
- The AsOf company trend uses versioned seller daily rows. A week with more than one non-null market `compatibility_key` remains on the shared x-axis but emits null seller, market median, p20, and p80 values. Cache schema v8 carries the active method; AsOf fingerprints also include the annual-only table's maximum date and `updated_at`, while legacy source fingerprinting remains snapshots plus statistics.
- `contract_price_daily_statistics.method_version` remains nullable in storage for application rollback compatibility. The model and all new writers still assign a method. Migration `2026_08_06_000001` is retry-safe after partial MySQL DDL, reruns the full backfill, and reports duplicate old daily-stat identities before key replacement. The method-aware unique key does not repair SQL's nullable-key rule for unit rows with NULL consumption; application date writers replace their own rows and rerun tests prove they do not create duplicates.
- Historical date and contract universes are unions of exact-date snapshots and components. A component-only contract has no safe historical household or classification identity and becomes exactly three unavailable `unclassified` results with reason and flag `missing_historical_snapshot_identity`. Snapshot-only canonical evidence remains valid. Apply rejects empty or incomplete three-consumption result sets before deleting old rows; diagnostic preview can remain partial.
- `AnnualCostCompatibilityKey` now builds both current and historical identities from exactly method version, calculation basis, estimate method, and estimate basis. Pricing basis is evidence provenance and does not split otherwise equivalent fixed or Spot calculations.
- AsOf Spot accepts a stored rolling row only when `period_end` equals the target. Missing or invalid target evidence goes to strict exact-window hourly reconstruction or unavailable; no older rolling level is carried forward.
- Daily aggregate pricing/calculation/estimate basis counts include available contributors only. Unavailable results remain visible only in the separate `unavailable_reasons` map. Date/command summaries can still count all typed results.
- Blocker-fix verification completed with Pint, all versioned annual/AsOf Spot tests, the statistics test set, migration-focused tests, and the full Laravel suite (2,007 tests and 7,651 assertions). No production-data dry run, activation, deployment, or production mutation was done.
- `AnnualSeriesCompatibility` now owns public annual-series cutovers. Null keys are one legacy regime. A period with null plus a named key is mixed. Mixed weekly/monthly periods and the first daily or aggregated point after a transition are null. A transition inside a mixed period consumes the one transition gap; an exact boundary transition nulls the new period. Annual deltas compare normalized keys through the same helper.
- The main statistics page, homepage, article annual comparison, article Spot win rate, AsOf company trend, and market-insight deltas use the shared guard. Their prepared payload schemas were bumped where needed. Legacy company trend output remains unchanged.
- Spot win rates first process the complete trailing window for transition gaps, then retain only each segment's latest regime. The Spot and comparison segment keys can differ from each other, but neither side can pool its rolling and forward evidence around 2026-05-01.
- Aggregate market insights no longer require one compatibility key across unrelated segments. Latest and previous rows are mapped deterministically by segment, then both weighted endpoints use only the same segment intersection whose key is unchanged. Segment-specific insight still requires one unchanged key.
- On the latest expected-basis unit date, the main statistics page accepts an active annual row only with the expected pricing basis or `mixed_evidence`. A canonical-on calculation followed by feature-off recalculation can leave canonical AsOf audit rows, but those rows cannot become public in feature-off mode.
- Company AsOf seller-row support remains active and covered: changing the active annual method does not remove a comparison when a matching versioned seller row exists. The configured active method remains legacy; no activation occurred.
- Cutover hardening verification passed targeted Pint, 146 annual/statistics tests with 816 assertions, and the full Laravel suite with 2,015 tests and 7,675 assertions. The production asset build and `git diff --check` also passed.
- A full local dry run and apply over the available production-derived snapshot (2026-01-21 through 2026-07-31) completed 191 dates with zero failed dates. It produced 265,200 typed results, 183,532 available annual rows, 81,668 unavailable results, and 6,465 aggregate rows. Estimate methods included 16,043 forward-curve Spot results and 17,933 rolling-365 Spot fallbacks. The first proven forward Spot date was 2026-05-01.
- The unavailable results are explicit: 74,052 are the three consumption slots for 24,684 component-only contract-dates that lack a safe historical statistics identity; 6,788 preserve old per-consumption unavailability; 748 lack exact-date Spot shape evidence; the remaining small counts are canonical exclusions, unsupported component evidence, or the annual sanity ceiling. No unavailable result enters an aggregate.
- A fresh production snapshot sync cannot pass before deployment because production does not yet have the new `contract_price_annual_costs` table. The existing local production-derived snapshot remained unchanged by that failed sync. After the migration deploys, repeat the read-only sync and full dry run against the current production data before any production `--apply` or method activation.
- AsOf-specific page copy is conditional on the active annual method. Legacy production copy stays unchanged during the shadow-data release; after activation, the page explains as-of curves, exact-date fallbacks, and compatibility gaps.
