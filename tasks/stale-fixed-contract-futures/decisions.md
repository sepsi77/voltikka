# Decisions

- Production evidence on 2026-08-05 showed that FI EEX Base data and its checkpoint were current through trade date 2026-08-04. The newest forecast was still from 2026-08-01 and used trade date 2026-07-31 because the scheduled forecast was deferred on 2026-08-02 through 2026-08-05.
- The freshness gate used every active contract for interpretation coverage and publication order. Unrelated Spot and Hybrid/OpenEnded interpretation activity therefore blocked a forecast that consumes only current `fixed_term_6`, `fixed_term_12`, and `fixed_term_24` energy-price statistics.
- Fixed-term forecast interpretation checks now start from checkpoint active IDs. They use current contract facts and `ContractStatisticsSegmentClassifier` in the expected `ContractPriceBasis`, and keep only `Household`, `Both`, or null-target contracts in the three forecast segments. This reuses the statistics classification and household filter instead of adding parallel rules.
- Retail-premium freshness still checks all active checkpoint contract IDs. EEX, checkpoint, fixed-statistic, relevant interpretation publication, and publication-order checks stay unchanged.
- Verification: the focused forecast and freshness suites passed 24 tests with 121 assertions. The regression test proves that a pending Spot interpretation and a Hybrid/OpenEnded publication during statistics do not block the canonical fixed-term forecast, while retail freshness still blocks on the pending Spot contract. The existing relevant Fixed6 publication-order test still blocks the forecast.
- A read-only check with the patched local code against production data reports the forecast gate as ready with no failures. The 6, 12, and 24 month hedge calculations all select the newer 2026-08-04 futures trade date. A full public-database dry run was stopped because its historical model loop makes many remote read queries; the focused check proves the corrected gate and current hedge selection without that unnecessary load.
