# Decisions

- Treat the Carbon frame as the point where the time limit expired, not as evidence that Carbon is the root cause. The repeated `MAX(trade_date)` futures queries in the breadcrumbs are the primary lead.
- Keep `FixedTermHedgeCostService` unchanged because its behavior feeds stored scheduled forecasts. The shared live-pricing provider will load the distinct FI Base trade dates once and resolve strict prior vintages in memory.
- Add exact-vintage retail-premium lookup boundaries. Existing as-of-date entry points resolve one vintage and delegate, while the market-reset provider passes its memoized vintage and requests only the candidate kinds that it can use.
- The provider now performs one ordered/distinct FI Base `trade_date` scalar query per shared provider lifetime. It resolves strict prior dates in memory and uses `array_key_exists` so a null prior-vintage miss is a real memo entry.
- Exact-vintage reset lookups honor requested kinds. A provider request for `month` does not run the derived quarter-month query. The full retail-premium reset entry point still requests all prior candidates.
- Direct comparisons replace `whereDate` only in the changed futures lookup paths. Exact-vintage reads use an index-friendly half-open range from the plain `YYYY-MM-DD` trade date to the next plain date. This accepts the synced SQLite snapshot's plain dates and test datetimes while MySQL can compare and index its DATE column directly.
- Bind `MarketReferenceCurveProvider` as scoped, not singleton. One request, command, or job shares its available-date and curve memos, but the next Octane or queue lifecycle starts with fresh market data.
- Focused provider/service tests and related market-reset, supplier-adjusted, and Spot-forward tests pass. Query-listener coverage proves one available-date query, no repeated null query, no provider-side `MAX(trade_date)`, one service-side vintage resolution, and no quarter-month query for month-only references.
- The additional `PricingBucketFilterTest` run has one unrelated Livewire test-harness failure in `test_toggling_a_bucket_adds_and_removes_it_and_tracks_the_first_click`: Livewire rejects the test snapshot before its first assertion. The other 22 tests in that file pass. None of the changed pricing-provider files participate in the canonical-disabled test setup, and this task does not change that test.
