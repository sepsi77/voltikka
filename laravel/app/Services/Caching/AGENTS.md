# AGENTS.md

Context for caching services under `laravel/app/Services/Caching`.

## `ContractPageCacheVersion`

Purpose:
- provides a cheap source-data fingerprint for high-traffic public contract listing and detail pages
- used by Livewire components that cache prepared view data until tomorrow, while still busting when contract/price source data changes

Important semantics:
- this is not full-response caching; components cache prepared view payloads to avoid expensive repeated contract list/detail assembly on canonical first-page loads
- `ContractListCacheService::getVersion()` is the primary pricing-data invalidation signal. A complete successful import activates it only after a verified staged replacement. A non-dry EEX fetch still invalidates immediately after writing prior-date FI Base data because futures change Spot and reset annual totals
- aggregate table counts/max dates are included to protect local/manual/test data changes and spot-average-dependent price calculations
- avoid expensive full-table JSON hashes here; this method runs to decide whether cached page payloads can be reused. `ContractPriceCacheEvidence` adds one bounded active-contract identity query (IDs, source/publication snapshot ownership and publication status), not full source or interpretation payloads
- calculated-cost payload v6 adds typed monthly included-energy package data
- payload v7 is the card/detail canonical-only current-value and real-term offer-copy boundary
- payload v8 is the company/SEO canonical offer-membership and JSON-LD boundary
- payload v9 adds exact typed canonical offer terms
- payload v10 adds real-term totals and offer savings for short BaseOnlyHybrid outcomes
- calculated-cost schema v11 invalidates old membership after `other` cadence recurring resets became listed estimates
- calculated-cost schema v14 adds the forward-Spot evidence payload and invalidates old rolling-Spot sort values
- `CalculatedCostPayloadSchema::VERSION` is the one calculated-cost shape version used by list, company, ranking, and prepared-page cache keys
- `ContractPageCacheVersion` keeps its own prepared-view wrapper version and also includes the shared `cs{version}` marker plus `PricingMode::cacheMarker()`
- Its Spot fingerprint includes all FI average period types, including corrected local rolling rows. Updated time, hour count, and overall/day/night price sums detect a same-date refresh even when row count and evidence dates stay unchanged.

## Shared annual price generations

- `ContractPriceCacheLifecycle` owns one atomic active descriptor: public integer version, private UUID generation, and creation time. The descriptor is always reread. When absent, bootstrap under the transition lock from the legacy contract version; legacy dated payloads are not imported as a verified generation. Cold test/local builds still work.
- `ContractListCacheService::refresh()` builds all eight presets privately and releases each hydrated set. Company/5,000 receives exactly the candidate/5,000 metric set, never the active accessor. Each write must succeed. Every required stored entry must match its expected serialized digest before activation. Active evidence must also remain unchanged during the build.
- Activation, immediate invalidation, bootstrap, cold payload writes, and bounded physical cleanup use the shared short transition lock; candidate calculations and candidate payload writes do not hold it. Cold calculations also run outside the lock; only their manifest/payload write is protected against cleanup. Activation compares the reread starting descriptor, not a request memo. Any interpretation/EEX/manual `bumpVersion()` invalidates immediately through the same lock and rejects an older candidate. Company and list public versions now share this descriptor.
- Active list/company payloads use non-expiring writes. Generation keys retain schema and immutable pricing-mode markers but no calculation-day suffix. Rankings can expire, but rebuild from shared retained annual metrics, not current-date calculator calls. There is no midnight refresh schedule.
- Each generation tracks only its own written payload keys. Before switching the active pointer, the transition durably records the previous generation in `contract_price_cache_retired_v1` with a one-hour grace deadline. Failed candidates are registered on retirement. Manifests and retirement records do not expire: a cache TTL cannot physically reclaim abandoned MySQL rows. Payloads also remain until explicit cleanup, so in-flight readers retain them throughout grace. A late cold writer now rejects a changed active descriptor under the same lock before writing its manifest or payload; it cannot publish into an invalidated generation.
- `contracts:cleanup-price-cache` runs every five minutes with one-server and overlap protection. Each run examines at most 20 tracked generations and attempts at most 100 payload deletions. It rereads the active generation under the transition lock and never deletes it, even if an interrupted pointer write left it in the retirement index. It physically forgets exact tracked keys, records partial progress in the manifest, and removes the manifest/index entry only after successful deletion. Failures retain durable retry state and return a non-zero command exit for central scheduler reporting. Cleanup never scans the cache table, flushes a store, truncates a table, or deletes unrelated payloads or locks. Cleanup failures cannot undo activation. If cleanup-state persistence fails before activation, the pointer is not switched.
- `ContractPriceCacheEvidence` guards cached canonical prices against current active pointed/published identities, snapshot ownership, and publication status. A changed, missing, inactive, or mismatched cached identity returns a typed exclusion with no old numeric/current/offer facts. Cold builds apply the same guard. **Never use `relational_pricing_published` as a canonical eligibility gate or fingerprint input.** Corrected canonical pricing can be published while relational writes are blocked precisely because they omit a known hidden increase. With current publication identity, the typed canonical outcome alone decides listability; corrected deceptive totals remain listed and genuinely incomplete/conflicting canonical outcomes remain excluded. Pointer-free legacy/local fixtures retain cold behavior. A new safe contract with no cached facts can still use existing direct-consumer fallback. Company cache and ranking memo keys include this evidence fingerprint; prepared-page fingerprints do too, so prepared output cannot bypass the guard.
- This is not a database snapshot. Availability and interpretation identity checks stay current. Retained phase prices, annual totals, and offer facts can remain from the previous calculation across midnight until explicit refresh; this is intentional and is not a claim that the previous phase or offer is still current today. Direct custom calculations, non-selected detail tiers, and CompanyDetail remain outside the retained annual-generation boundary. No canonical calculator semantics are changed.
- `ContractListCacheService::calculatedAt($consumption)` reads the stored payload's actual calculation timestamp; ranking wrapper v3 retains it in metadata. Ranking and prepared-page keys also include the private generation identity, so descriptor loss/bootstrap cannot collide with an older entry that has the same public integer version. Detail `heroVerdictNote()` uses the stored timestamp for `rankConsumption()` in Europe/Helsinki and omits the date when unavailable. It never labels retained rankings with the request date.
- `contracts:warm-cache --refresh` uses the staged replacement. The normal warmer retains read-through behavior. Required import refresh failure is `price_cache_refresh`; statistics timestamps and statistics-cache queue scheduling are unchanged.

## Bounded conflict recovery

Only `ContractPriceCacheConflict` is retryable: its named factories mean verified `evidence_changed` or `generation_changed`. Cold list reads have two total attempts. Each attempt rereads the active descriptor and evidence; no unpublished result or request memo crosses the retry. The outer prebuild evidence must still match before write, so a newly stable result cannot be guarded or memoized under an older identity. Company reads own the same two-attempt budget and disable nested list retries; they check their evidence-derived key before writing. No sleep, calculation lock, stale-price return, relational fallback, or fabricated zero is permitted.

A staged refresh has two total full candidate attempts, not two per preset. It resets canonical Spot assumptions, episode anchors, Spot estimates, and the shared EEX provider memo before each candidate. Each attempt uses new contracts, a fresh descriptor/evidence fingerprint, and a new private UUID. A failed candidate must be durably retired with `required: true` before retry; retirement failure escapes as a storage error. Existing scheduled cleanup reclaims its tracked keys after grace. Active-pointer writes are never reversed, including independent interpretation/EEX invalidations. Storage writes/readback use a separate non-retryable typed exception with closed diagnostic reasons. Unknown errors and invalid payloads also escape without retry.

`bootstrap/app.php` renders only exhausted typed conflicts as a plain Finnish HTTP 503, with `Retry-After: 30` and `Cache-Control: no-store, private`, and excludes only that conflict class from automatic reporting. CLI callers still receive the typed exception. A proven complete full contract import can defer completion after exhaustion; other required failures still fail the checkpoint and emit one safe aggregate Issue. Unknown runtime exceptions retain normal reporting. Cost is bounded at two list/company attempts or two full eight-preset-plus-company candidates per call. This is not a source database snapshot.

`refresh()` accepts an optional import candidate guard. It checks the statistics-bound active/publication evidence and current run/claim ownership before the existing promotion boundary. A typed guard conflict uses the same two-total-candidate budget and durable retirement; it does not add retries per preset. No publisher mutex or source snapshot guarantee is added. Deferred imports re-run current-date statistics before a later refresh and bind completion-time proof to the resulting generation/fingerprint. That proof is checked at completion writes, not as a permanent cache-generation condition on morning readers. Later EEX/manual invalidations keep their existing behavior; fixed-term readers retain scoped publication-order recovery. See `../ContractImport/AGENTS.md` for the checkpoint row fence and bounded schedule.
